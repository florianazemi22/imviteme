# 2. Theme architecture

**Goal:** adding theme #13 is two days of design work and zero days of backend
work. Everything below exists to make that true and to keep it true.

---

## 2.1 The big call: Twig templates + islands, not a Vue SPA

Your stack is Vue 3 + TS, so the instinct is "themes are Vue components". I'd
push back for the public renderer.

**The constraint that decides it:** the guest-facing invitation page is opened by
hundreds of guests on mid-range Android phones over patchy mobile data, in
Prishtina, Lahore, Casablanca and Guayaquil. It must be usable in under 2.5s LCP
on a throttled 3G connection. The editor, by contrast, is opened by one paying
customer on a decent connection who will tolerate a 400KB bundle.

Those are different products. Building them from one SPA means the guest pays
for the editor's weight.

**Recommended split:**

| | Editor | Public invitation |
|---|---|---|
| Delivery | Vue 3 SPA, Vite, Pinia | Symfony + Twig, server-rendered |
| Bundle budget | whatever it needs | **< 60KB JS gzipped**, < 40KB CSS |
| Interactivity | full | islands only: RSVP form, gallery lightbox, audio control, countdown, map embed |
| Preview | debounced iframe of the real render endpoint | n/a |

Islands: small Vue 3 components mounted individually with `createApp()` on
`[data-island]` elements, code-split per island, lazily mounted via
`IntersectionObserver`. Don't reach for Astro/Nuxt — Symfony + Twig + a handful
of `createApp` calls is less infrastructure for a solo developer, and
`symfony/ux-vue` (`vue_component()` Twig function) handles the mount plumbing if
you want it.

**Why the iframe preview is the right editor UX here:** the editor posts a draft,
the server renders it at the real render endpoint, the iframe reloads (debounced
~350ms, `srcdoc` or a `?preview=<draft_token>` URL). You get:
- Preview output byte-identical to published output. No "it looked different
  before I paid" support tickets — which in this product are brutal, because the
  customer is emotionally invested and the artefact is a wedding invitation.
- One rendering implementation, not two.
- Theme authors write one template, not a Twig template plus a Vue component.

The cost is a ~200ms round trip per keystroke-batch. That's acceptable, and you
can mask it with an optimistic overlay for pure text edits.

**When to abandon this and add a Node SSR service:** if themes grow to need
shared reactive state across sections (a scroll-linked narrative where section 4
reacts to section 1's animation progress), or if you hire designers who will only
work in SFCs. Both are real futures. The manifest and section vocabulary below
are renderer-agnostic, so switching the renderer later is a rewrite of templates,
not of the data model. That's the escape hatch, and it's why the manifest matters
more than the template language.

## 2.2 What a theme is on disk

```
themes/nur/
  manifest.json           # the contract — validated in CI
  tokens.css              # design tokens only; no layout rules
  theme.css               # theme-specific layout/decoration
  sections/               # OPTIONAL overrides of core section templates
    hero.html.twig
    schedule.html.twig
  assets/
    fonts/                # self-hosted woff2, subset per script
    img/
    audio/default.m4a
  preview/
    latn.png  arab.png  deva.png    # generated by the fixture matrix, committed
  CHANGELOG.md
```

Core ships a default template for **every** section type. A theme overrides only
what it needs. A minimal new theme is `manifest.json` + `tokens.css` + a hero
override + assets — which is the "mostly design work" target.

## 2.3 The manifest

This is the contract. It is validated against a JSON Schema in CI, and an invalid
manifest fails the build.

```json
{
  "schema_version": 1,
  "code": "nur",
  "name": "Nur",
  "version": 4,
  "tier": "premium",

  "supported_sections": [
    "hero","quote","countdown","story","schedule","venue",
    "gallery","rsvp","gifts","dress_code","faq","contacts"
  ],

  "capabilities": {
    "photo_slots": 6,
    "hero_image_aspect": "3/4",
    "supports_bilingual_split": true,
    "supports_music": true,
    "max_headline_graphemes": 42
  },

  "scripts": {
    "latn": {
      "fonts": {
        "display": "Cormorant Garamond",
        "body": "Inter",
        "accent": "La Belle Aurore"
      },
      "line_height": { "display": 1.1, "body": 1.6 },
      "letter_spacing": { "display": "0.02em" }
    },
    "arab": {
      "fonts": {
        "display": "Aref Ruqaa",
        "body": "Noto Naskh Arabic",
        "accent": "Aref Ruqaa"
      },
      "line_height": { "display": 1.6, "body": 1.9 },
      "letter_spacing": { "display": "0" },
      "font_size_scale": 1.08
    },
    "deva": {
      "fonts": { "display": "Tiro Devanagari Hindi", "body": "Noto Sans Devanagari", "accent": "Tiro Devanagari Hindi" },
      "line_height": { "display": 1.5, "body": 1.85 },
      "font_size_scale": 1.04
    },
    "cyrl": { "fonts": { "display": "Cormorant Garamond", "body": "Inter", "accent": "Inter" },
              "line_height": { "display": 1.15, "body": 1.6 } },
    "grek": { "fonts": { "display": "Cormorant Garamond", "body": "Inter", "accent": "Inter" },
              "line_height": { "display": 1.15, "body": 1.6 } }
  },

  "motion": {
    "preset": "veil",
    "intensity": "medium",
    "sections": {
      "hero":     { "enter": "mask-reveal", "duration": 1200, "stagger": 80 },
      "schedule": { "enter": "fade-up",     "duration": 600,  "stagger": 60 },
      "gallery":  { "enter": "scale-in",    "duration": 500 }
    }
  },

  "audio": {
    "default_track": "assets/audio/default.m4a",
    "control_style": "floating-minimal"
  },

  "palettes": [
    { "code": "ivory", "is_default": true, "tokens": { "--c-bg": "#FBF7F0", "--c-ink": "#2A2521", "--c-accent": "#B08D57" } },
    { "code": "emerald", "tokens": { "--c-bg": "#0E1F1A", "--c-ink": "#F0EAE0", "--c-accent": "#C9A227" } }
  ]
}
```

### The rule that makes non-Latin scripts safe

**`scripts` must contain an entry for every script listed in
`themes.supported_scripts`, and CI fails if it doesn't.**

This is the single highest-value constraint in the whole theme system. The
failure it prevents: a designer picks a gorgeous Latin display face, an Arabic
customer buys the theme, the browser falls back to a system font, and the
invitation looks like a 1998 GeoCities page at the most emotionally significant
moment of someone's life. The manifest makes the substitute face an explicit,
reviewed design decision rather than a browser accident.

A theme that hasn't been designed for Devanagari simply doesn't list `deva` in
`supported_scripts`, and the theme picker filters it out for that customer. That
is a perfectly honest outcome — better than shipping a broken one.

## 2.4 Design tokens

`tokens.css` contains **only** custom properties. No selectors beyond `:root` and
the script/direction scopes.

```css
:root {
  /* colour */
  --c-bg: #FBF7F0;  --c-ink: #2A2521;  --c-accent: #B08D57;
  --c-muted: color-mix(in oklch, var(--c-ink) 55%, var(--c-bg));

  /* type: ROLES, never font names in templates */
  --font-display: "Cormorant Garamond", Georgia, serif;
  --font-body: Inter, system-ui, sans-serif;
  --font-accent: "La Belle Aurore", cursive;

  /* fluid scale — the long-name defence */
  --fs-display: clamp(2rem, 9vw, 4.5rem);
  --fs-h2: clamp(1.375rem, 5vw, 2.25rem);
  --fs-body: clamp(1rem, 2.6vw, 1.125rem);

  --lh-display: 1.1;
  --lh-body: 1.6;

  /* spacing — logical, never left/right */
  --space-inline: clamp(1rem, 5vw, 3rem);
  --space-block: clamp(2rem, 9vw, 6rem);

  --radius: 2px;
  --motion-duration: 600ms;
  --motion-ease: cubic-bezier(0.22, 1, 0.36, 1);
}

/* Script overrides, emitted server-side from the manifest */
:root[data-script="arab"] {
  --font-display: "Aref Ruqaa", "Noto Naskh Arabic", serif;
  --font-body: "Noto Naskh Arabic", system-ui, sans-serif;
  --lh-display: 1.6;
  --lh-body: 1.9;
  --fs-display: clamp(1.9rem, 8vw, 4rem);
}
:root[data-script="urdu"] {           /* Nastaliq is its own beast */
  --font-display: "Noto Nastaliq Urdu", serif;
  --font-body: "Noto Nastaliq Urdu", serif;
  --lh-display: 2.1;
  --lh-body: 2.2;
}

@media (prefers-reduced-motion: reduce) {
  :root { --motion-duration: 1ms; }
}
```

**Templates reference roles, never font names.** `font-family: var(--font-display)`.
A template containing a literal font name is a CI failure (grep check, five lines).

## 2.5 Motion

Do not let each theme hand-roll animation timelines. You'll get twelve
incompatible implementations, twelve performance profiles, and twelve
`prefers-reduced-motion` bugs.

**Core owns a small, closed vocabulary of named effects**; the manifest selects
and tunes them:

| effect | description |
|---|---|
| `fade-up` | opacity + 16px translate on enter |
| `mask-reveal` | `clip-path` inset wipe, direction-aware |
| `scale-in` | 0.96 → 1 with opacity |
| `letter-cascade` | per-grapheme stagger — **Latin/Cyrillic/Greek only** |
| `parallax-layers` | 2–3 background layers, scroll-linked |
| `petal-fall` | decorative particle layer, canvas, capped at 30 particles |
| `ken-burns` | slow hero image drift |

Implementation:

- **CSS scroll-driven animations** (`animation-timeline: view()`) where supported
  — zero JS, GPU-composited. Baseline in Chrome/Edge 115+ and Safari 26; use
  `@supports (animation-timeline: view())` and fall back to IntersectionObserver.
- **[Motion](https://motion.dev) (`motion`, MIT, ~5KB for the mini bundle)** for
  the JS path. I'd pick this over GSAP specifically to avoid ever having to think
  about GSAP's licensing terms for a commercial product with a template
  marketplace. GSAP's licensing became much more permissive in 2025, but "I never
  have to check" is worth more than GSAP's extra features here.
- Everything respects `prefers-reduced-motion` at the token level (above), so a
  theme cannot accidentally ignore it.

**`letter-cascade` must be script-gated.** Splitting text into per-character spans
destroys Arabic contextual shaping (letters stop joining) and breaks Devanagari
conjuncts. The effect registry declares `"scripts": ["latn","cyrl","grek"]` and
the renderer silently substitutes `fade-up` otherwise. This is exactly the kind
of bug that ships to production and gets discovered by a customer.

**If MP4 export becomes a Phase-2 feature** (see [README](README.md) pushback),
this declarative motion vocabulary is what makes it tractable: you render the
invitation in headless Chromium and drive a deterministic timeline, rather than
trying to screen-record arbitrary per-theme JavaScript. Worth keeping in mind
when you're tempted to let a theme "just add a little custom GSAP".

## 2.6 Music

One core `<AudioController>` island. The theme supplies the default track and the
control's visual style — nothing else.

Non-negotiable behaviours:

- **Never autoplay with sound.** iOS Safari and Chrome will block it, and in
  several of your target cultures an invitation that blares music when opened in
  a quiet room is actively offensive. Ship a visible, tappable "play" affordance
  that appears immediately.
- Persist mute state in `sessionStorage`.
- Audio element `preload="none"`; load on first tap. Never spend a guest's mobile
  data on a track they didn't ask for.
- Pause on `visibilitychange`.

**Licensing — the part that can actually hurt you.** Do not build a library of
recognisable songs. Options, in order of how much I'd recommend them:

1. **Commission 8–15 original instrumental tracks** across the aesthetics you
   need (Balkan/çifteli, oud/Arabic, Indian classical, piano, ambient, Latin
   guitar). A composer on Fiverr/SoundBetter with a full buyout, work-for-hire
   contract costs €100–400 per track. You own it outright, forever, with no
   per-end-user licensing question. For ~€3,000 total this problem disappears
   permanently. **This is what I'd do.**
2. **Production-music library (Epidemic Sound, Artlist, Musicbed).** Their
   standard subscriptions license *your* content, not content your customers
   publish on pages you host. You'd need their partner/API/enterprise tier. Get a
   written answer before relying on it — see [OPEN-QUESTIONS](OPEN-QUESTIONS.md).
3. **Let the host upload their own audio.** Shifts primary liability to them via
   ToS, but you're still a host: you need notice-and-takedown and you'll get the
   occasional rightsholder complaint. Fine as a paid add-on with a clear warning,
   not as the default.
4. **Embedding Spotify/YouTube.** Don't. Autoplay is blocked, the embed weighs
   more than your entire page, it's ugly, and it breaks offline.

Religious audio (Quran recitation for nikah invitations, liturgical music for
baptisms) is culturally expected in several target markets. The *text* is public
domain; specific *recordings* are copyrighted. Commission or license these
explicitly — and give the host an easy "no audio" option, because preferences on
this are strong and divided.

## 2.7 The fixture matrix — how "adding a theme is design work" stays true

This is the mechanism. Without it, the promise decays within four themes.

**A canned set of content fixtures** lives in `tests/fixtures/invitations/`:

| fixture | what it stresses |
|---|---|
| `latn-short` | "Ana & Luis" — the happy path every designer tests |
| `latn-long-de` | "Maximiliane Schörghuber-Wittelsbach & Konstantin Aleksandrov" |
| `sq-diacritics` | "Ardhmëria Krasniqi-Gashi" — ë, ç ascender/descender collisions |
| `tr-casing` | "İdil Çağlayan" — dotted/dotless i, `text-transform` traps |
| `arab-rtl` | Arabic names + mixed Latin venue name (bidi) |
| `urdu-nastaliq` | Nastaliq line-height and descender overlap |
| `deva-hindi` | Devanagari conjuncts and the shirorekha |
| `cyrl-sr` | Cyrillic in a Latin display face |
| `grek` | Greek accents, uppercase tonos rule |
| `hani-zh` | CJK line-breaking, no word spaces |
| `he-rtl` | Hebrew + Latin mixed |
| `emoji-names` | because people do this |
| `max-content` | 9 sub-events, 6 venues, 24 FAQ items, 40 photos |
| `min-content` | names + one date, everything else empty |

**A Playwright job renders every (theme × fixture × {light, dark} × {360px,
430px, 768px, 1280px}) combination** and asserts:

1. No horizontal overflow: `document.scrollingElement.scrollWidth <= clientWidth + 1`.
2. No element overflows its container (`el.scrollWidth > el.clientWidth` on
   anything with `overflow: hidden`).
3. No text clipped: compare `scrollHeight` to `clientHeight` on text blocks.
4. Every rendered glyph resolves in a loaded font — no `.notdef` boxes. Check via
   `document.fonts.check()` per script plus a pixel-diff against a known-good
   baseline.
5. Screenshot diff against the committed baseline (`pixelmatch`, 0.1% threshold).
6. Lighthouse/`web-vitals` budget on the `max-content` fixture: LCP < 2.5s on
   simulated Slow 4G, JS < 60KB gz.

That's ~14 fixtures × 4 widths × N themes. At 12 themes it's ~672 screenshots —
a few minutes in CI, and it is the entire reason you can ship theme #13 in two
days without fear.

**Run this matrix on the very first theme, before building the second.** The
temptation will be to add it "once there are a few themes". By then three themes
will have hardcoded `left: 24px` and you'll be retrofitting.

## 2.8 Long names and layout resilience

Concrete rules, all cheap, all enforceable by lint:

- **Fluid type with `clamp()`** everywhere; no fixed `font-size` on headlines.
- **`text-wrap: balance`** on headings, `text-wrap: pretty` on body (progressive
  enhancement; harmless where unsupported).
- **Container queries** (`@container`) rather than viewport media queries for
  section-internal layout, so a section behaves correctly in the editor's narrow
  preview pane too.
- **Never a fixed-height name container.** Names are the one field guaranteed to
  break your design; let them grow and push the layout down.
- **`hyphens: auto` with `lang` set correctly** — critical for German compounds,
  harmful if `lang` is wrong.
- **`overflow-wrap: anywhere` on all user content containers** as a last-resort
  guard against an unbroken 40-character surname.
- **A grapheme budget per theme** (`capabilities.max_headline_graphemes`), used by
  the editor to show a soft warning — not a hard limit. Count graphemes with
  `Intl.Segmenter`, not `.length`; a Devanagari conjunct or an emoji ZWJ sequence
  is many code units and one visual character.
- **No `text-transform: uppercase`** on user content. It's meaningless for Arabic
  and Devanagari, it silently drops the tonos in Greek, and it produces `IDIL` for
  Turkish `İdil` unless the `lang` attribute is right. If a theme's aesthetic
  needs caps, apply it only under `[data-script="latn"]` and use a font's small-caps
  feature rather than `text-transform`.

Details and the RTL rules in [03-i18n-and-typography.md](03-i18n-and-typography.md).
